# Emergency alerts (inactive)

This package is isolated from the fuel summary runner and workflow. It makes no MAX or Telegram requests unless a caller explicitly constructs a reader, rewriter, sender and worker. The only accepted source is `https://max.ru/id5610084427_gos`; the only destination is `@benzinoren`. The sender requires a separate emergency Telegram bot token. No MAX send, reaction, join or subscription operation is present.

`PreparedMaxReader` accepts an already connected and independently authorized client, a verified channel ID, and a verified function producing canonical public post links. It calls only `fetch_history()` for that ID and does not connect, enumerate chats or read contacts. It is not wired to production. The installed `pymax.WebClient.connect()` login sync may itself receive other chats, messages and contacts; this package cannot guarantee their exclusion. The public channel ID, post link format, authorized read path and MAX permission are not yet verified. Do not attach the existing user session until these conditions are resolved.

`EmergencyPipeline` filters eligible posts, asks Gemini for a short rewrite, validates numbers, named places, status words and source vocabulary, and includes the complete original text and public source link in the Telegram message. Rejected or unavailable Gemini output falls back to the unmodified original, so a rewrite failure does not suppress a fresh official alert. The SQLite store persists message IDs, revisions, detection and send timestamps, and a single destination. Repeated polls after a pre-send error can retry. A send that might have succeeded remains `claimed` and requires manual reconciliation before retry; automatic resend could duplicate an alert. Edited or removed posts also require review. Posts older than 15 minutes are not sent, including after restarts. Before the first send, the Telegram adapter verifies the chat username and the separate bot's posting rights, and rejects the fuel summary bot token when available in `BOT_TOKEN`.

To activate after authorization, provide a verified channel ID and post link mapping, a connected source with documented permission, a dedicated Telegram bot token with rights to post to `@benzinoren`, and a durable SQLite path. Run the worker as its own service, with independent monitoring and state backups. Keep the fuel summary workflow unchanged. Verify the sole destination with a safe bot identity and chat check before enabling real sends. No real MAX read or Telegram publication has been performed for this package.
